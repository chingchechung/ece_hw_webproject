## Change and scope

`showcase3d/src/main.js` adds `syncFullscreenButton()`. The function reads
`document.fullscreenElement` and updates the existing button:

| Actual Fullscreen API state | Visible label | Accessible label |
| --- | --- | --- |
| No fullscreen element | Fullscreen | Enter Fullscreen |
| Fullscreen element present | Exit Fullscreen | Exit Fullscreen |

Synchronization runs during initialization, on `fullscreenchange`, and after
the existing click handler finishes, including API rejection. The existing
`requestFullscreen()` / `exitFullscreen()` calls, failure message and driving
focus behavior are preserved. There is no independent fullscreen boolean.
Button exit, native Escape and other browser API exits use the same event.
Browser F11 is separate and is not treated as an application fullscreen element.

The runtime source change is ten added lines in main. No HTML source, CSS,
layout/control set, graphics settings, presenter/debug permissions, rendering,
physics, 2D/3D switching, validation, question/answer logic, launcher, Lite,
GUI, schemas or public assignment files change. The existing package version
remains `1.0.0-rc1`; no tag, merge or deployment is part of this fix.

## Regression evidence

Two new tests extend the existing **windowed Chromium navigation suite**;
all five previous navigation tests remain unchanged. They run on the normal
player UI, without presenter/debug flags:

- Check initial text/ARIA, real button entry, button exit, a second entry and
  native Escape exit, recording actual `fullscreenchange` states.
- Load a synthetic v2 five-question assignment in a disposable nested HTTP root,
  drive with real held keys, answer one question correctly, spend part of the
  map allowance, then compare the entire attempt, maze, assignment, view and
  geometry-rebuild count after each transition. Progress is earned through the
  existing game, never injected through a state setter.
- Simulate rejected entry and exit API promises in the test page. The label
  follows the actual browser state after either rejection and after recovery.
- Retain the existing harness checks for uncaught JavaScript/console errors,
  unexpected external runtime requests, screenshots and Playwright traces.

On Linux the Escape test uses X11/XTest through Python's standard-library
`ctypes`, under the existing Xvfb display. A CDP-simulated page key does not
invoke Chromium's native fullscreen exit. The test sends the real browser key;
it does not replace Escape with a scripted `exitFullscreen()` call.

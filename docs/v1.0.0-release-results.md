The [first tag-triggered publication attempt](https://github.com/chingchechung/ece_hw_webproject/actions/runs/39920969503)

logs show `actions/checkout@v4` fetched the correct annotated tag and then
overwrote **only its runner-local tag ref** with the commit SHA. Independent
remote inspection confirmed that the authoritative tag object remained
`8bf5b2c…` and its target remained `adf0d2d…`.

The successful recovery workflow checks out the immutable commit SHA explicitly,
preserves and checks the original annotation/object/target, and runs the
unchanged publisher from the tested release source. It rechecks actual main CI,
both empty manifests and all runtime hashes, creates a draft, uploads the two
ZIPs, compares API digests and freshly downloaded bytes, rechecks main, and only
then publishes stable. Both the tag and latest-release API now return the same
published release and exact two asset hashes below. The recovery run is green;
the failed first attempt is retained as operational history.

The publication controller is deliberately specific to this one v1.0.0 release.
For future reuse, check out the verified commit explicitly to preserve annotated
tag metadata. Do not recreate or move v1.0.0 or retry creation of the existing
Release. No production application or package input changed during recovery.
